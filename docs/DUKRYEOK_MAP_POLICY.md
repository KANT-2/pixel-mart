# PIXEL MART — 덕력지도 운영정책

## 1. 문서 목적

본 문서는 PIXEL LOCAL의 핵심 기능인
**덕력지도**의 데이터 집계, 노출, 개인정보 보호 및 운영 기준을 정의합니다.

덕력지도는 특정 사용자의 위치를 표시하는 지도 기능이 아닙니다.

지역 안에 어떤 취향을 가진 사람들이 얼마나 존재하는지를
익명 집계하여 보여주는 기능입니다.

---

# 2. 서비스 정의

덕력지도의 핵심 질문은 다음과 같습니다.

> "내 주변에도 나와 같은 것을 좋아하는 사람이 있을까?"

예:

분당구

- 오로치마루 팬 18명
- 나루토 팬 42명
- Retro Gamer 67명
- 키캡 수집러 31명
- PIXEL DESK 사용자 26명

사용자는 이를 통해
같은 지역에 존재하는 취향을 발견할 수 있습니다.

---

# 3. 핵심 운영 원칙

덕력지도는 다음 세 가지 원칙을 따릅니다.

1. 개인이 아닌 집단을 보여준다.
2. 정확한 위치를 보여주지 않는다.
3. 행동 데이터는 익명 집계한다.

---

# 4. 위치 노출 기준

덕력지도에는 다음 정보를 표시할 수 있습니다.

가능:

- 시
- 구
- 동 또는 서비스 Zone
- 지역별 익명 인원

불가 (다른 사용자에게 보이는 화면·데이터 기준):

- GPS 좌표
- 집 주소
- 건물
- 회사 위치
- 학교 위치
- 특정 사용자의 현재 위치

## 4.1 GPS 사용 범위 (본인 화면 전용)

GPS는 **본인**이 다음 두 가지를 할 때만 사용합니다.

- **동네 등록**: 내 동네·취향 설정에서 "내 위치로 찾기" → 가장 가까운 동·생활권을 찾아 채움
- **지도 조회**: 덕력지도에서 "내 위치로 보기" → 내 지역을 지도 중심으로 이동

어느 경우에도 GPS 좌표는 다른 사용자에게 알리거나 집계에 넣는 데 쓰지 않습니다.
서버에 저장되는 것은 사용자가 확인한 **지역 코드**뿐입니다.

1. **사용자가 요청할 때만 권한 요청**
   - "내 위치로 찾기"·"내 위치로 보기" 버튼을 눌렀을 때만 위치 권한을 요청합니다.
   - 페이지 진입·새로고침 시 자동으로 권한을 요청하지 않습니다.
   - 거부한 뒤에는 같은 화면에서 반복 요청하지 않습니다.
2. **좌표는 브라우저 안에서만 사용**
   - 좌표는 "가장 가까운 동·생활권 찾기"와 "지도 중심 이동"에만 사용합니다.
   - 좌표를 서버로 보내거나 저장·로그·분석에 사용하지 않습니다.
     서버 요청에는 찾은 **지역 코드**만 사용합니다.
   - 좌표는 화면을 벗어나면 폐기하며, localStorage·쿠키·URL에 남기지 않습니다.
     (URL에는 지역 코드만 남길 수 있습니다.)
3. **지도는 지역 단위로 표시**
   - 지도 중심은 좌표가 아니라 찾은 지역 블록입니다.
   - 본인 화면에도 정확한 현재 위치 점을 표시하지 않고, 해당 지역 블록을 강조합니다.
4. **동네 등록은 지역 코드만, 사용자가 확인 후 저장**
   - GPS로 찾은 지역(예: "성남시 분당구 판교")을 보여 주고, 사용자가 확인·수정한 뒤 저장해야 반영합니다.
   - 저장 시 서버에는 지역 코드만 보내며 좌표·정확도 값은 보내지 않습니다.
5. **GPS 없이도 모든 기능 이용 가능**
   - 거부·실패·미지원·서비스 지역 밖이면 안내 후 직접 지역 선택으로 이용합니다.
6. **다른 사용자에게 보이는 정보는 그대로**
   - 집계·표시는 계속 지역 단위 익명 인원이며, 5명 미만은 숫자를 공개하지 않습니다.

## 4.2 지도 표현 — 지역 집계 기반 장식 핀

덕력지도는 지역(구·동·생활권)을 픽셀 블록으로 그린 지도로 표현합니다.
다른 사람이 보는 핀은 **지역 집계 숫자만으로 프론트엔드가 그리는 그래픽**입니다.

예: API가 "A동: 나루토 팬 15명"을 주면
→ 프론트엔드가 A동 블록 안의 **임의 위치**에 나루토 픽셀 핀 3~4개를 흩뿌려 그립니다.

- 핀은 실제 특정 개인의 위치(뭉뚱그린 위치 포함)와 **전혀 무관**합니다.
  서버는 개인 좌표를 가지고 있지 않으며, 핀 위치 계산에 어떤 개인 데이터도 쓰지 않습니다.
- 핀 개수는 지역 인원에 비례하되 상한을 둡니다 (예: 약 4~5명당 1개, 지역당 최대 6개).
  핀 하나가 한 사람을 뜻하지 않으며, 인원은 "15명"처럼 지역 단위로 함께 표시합니다.
- 핀은 **5명 이상**인 지역에만 그립니다. 5명 미만 지역은 핀 없이 "소수의 팬이 있어요"로만 표시합니다.
- `isSample` 데이터로 그린 핀·지역은 "샘플 데이터"로 표시합니다.
- 핀을 눌러도 사용자 목록·프로필로 가지 않고, 지역 집계와 관련 상품·교환글로 연결합니다 (8장).
- 여러 취향은 필터(칩)로 바꿔 보거나 지역별 상위 취향 핀을 함께 표시할 수 있습니다.

이 방식으로 지도에 사람들이 모여 있는 느낌을 주면서도, 핀을 통해 개인을 추정할 수 없습니다.

# 5. 최소 집계 인원 정책

개인을 추정할 수 있는 소규모 데이터는 표시하지 않습니다.

예를 들어 최소 집계 기준을 5명으로 설정할 수 있습니다.

예:

판교 오로치마루 팬 12명

→ 표시 가능

판교 특정 캐릭터 팬 2명

→ 정확한 숫자를 보여주지 않음

화면 표시:

**5명 미만**

또는

**아직 소수의 팬이 있습니다.**

### 목적

지역과 취향의 조합이 지나치게 세분화될 경우
특정 개인을 유추할 가능성을 줄입니다.

---

# 6. 취향 집계 기준

덕력지도는 사용자가 직접 설정한 취향 정보를 기본 데이터로 사용합니다.

예:

- 관심 캐릭터
- 관심 작품
- 관심 상품 종류
- 선호 스타일

향후 검색 및 구매 데이터를 활용할 경우
개인을 직접 공개하지 않고 익명 통계로만 반영합니다.

---

# 7. 사용자 동의 원칙

사용자의 취향이 지역 통계에 반영되는 경우
서비스 정책에서 해당 활용 목적을 명확하게 안내합니다.

향후 실제 서비스에서는 사용자가
지역 기반 취향 집계 참여 여부를 설정할 수 있도록 확장할 수 있습니다.

---

# 8. 개인 프로필과 지도 분리

덕력지도에서 특정 집계 숫자를 클릭한다고 해서
해당 사용자의 목록을 바로 보여주지 않습니다.

예:

오로치마루 팬 18명

클릭 후:

가능

- 관련 상품
- 지역 Deskterior
- 공개 커뮤니티 콘텐츠
- 교환 게시물

불가

- 18명의 실제 사용자 목록
- 실제 이름
- 정확한 위치

---

# 9. 덕력지도 탐색 흐름

사용자 흐름 예:

분당구 선택
→ 오로치마루 팬 18명 확인
→ 오로치마루 선택
→ 관련 Deskterior
→ 관련 상품
→ 지역 교환
→ 커뮤니티 콘텐츠

덕력지도 자체가 목적이 아니라
다른 콘텐츠를 발견하는 시작점으로 사용합니다.

---

# 10. 지도 데이터 Empty State

특정 지역의 데이터가 부족한 경우
0명만 표시하고 끝내지 않습니다.

예:

"현재 판교에서 집계된 오로치마루 팬 데이터가 충분하지 않습니다."

다음 행동:

- 분당구 전체 보기
- 관련 상품 보기
- 내 취향 등록
- 관심 지역 등록

---

# 11. 인기 순위 정책

지역별 취향 순위를 제공할 수 있습니다.

예:

판교 인기 취향

1. Retro Game
2. Pixel Art
3. Naruto
4. Keycap
5. RPG

단, 지나치게 적은 데이터를 기반으로 순위를 만들지 않습니다.

최소 데이터 기준을 충족한 경우에만 표시합니다.

---

# 12. Local Wish Map 연계

덕력지도와 상품 수요 데이터를 연결할 수 있습니다.

예:

판교

오로치마루 팬 27명

↓

Orochimaru Figure 관심 사용자 18명

↓

공동구매 후보

이를 통해 취향 데이터가
실제 상품 수요 분석으로 연결될 수 있습니다.

---

# 13. Deskterior 연계

지역별 인기 Deskterior 콘텐츠를 제공합니다.

예:

판교 인기 Desk

- Retro RPG Desk
- Purple Pixel Desk
- Slime Gaming Desk

이를 통해

사람
→ 취향
→ 콘텐츠
→ 상품

으로 연결합니다.

---

# 14. 데이터 신뢰 정책

덕력지도 수치는 실제 사용자 활동을 기반으로 해야 합니다.

다음 데이터는 실제 사용자 데이터와 구분합니다.

- Mock Data
- Demo Data
- Sample Data

프로젝트 시연에서는 Mock Data를 사용할 수 있지만
실제 운영 서비스에서는 실제 사용자 수로 오인시키지 않도록 합니다.

---

# 15. 중복 집계 정책

동일 사용자가 같은 지역과 같은 취향에 여러 번 반영되지 않도록 합니다.

예:

사용자 A

오로치마루 클릭 50회

→ 팬 수 +50이 아님

→ 사용자 1명으로 집계

조회수와 사용자 수는 별도의 지표로 관리합니다.

---

# 16. 지역 변경 정책

사용자는 자신의 기본 지역을 변경할 수 있습니다.

잦은 지역 변경을 이용한 데이터 조작을 방지하기 위해
실제 서비스에서는 일정 기간 변경 제한을 둘 수 있습니다.

이번 프로젝트에서는 Mock 지역 선택으로 구현합니다.

---

# 17. 데이터 최신성

덕력지도 데이터에는 집계 기준 시점을 둘 수 있습니다.

예:

- 최근 30일
- 최근 90일
- 전체 누적

사용자에게 의미 있는 현재 취향을 보여주기 위해
장기적으로는 최근 활동 기반 집계를 권장합니다.

---

# 18. 이상 데이터 관리

다음과 같은 비정상 패턴은 집계에서 제외할 수 있습니다.

- 자동화된 반복 요청
- 동일 계정의 비정상 활동
- 다계정을 통한 조작
- 짧은 시간에 발생한 대량 이벤트
- 테스트 계정

# 22. 핵심 정책

덕력지도는

**"누가 어디에 있는지 알려주는 지도"**

가 아닙니다.

**"어느 지역에 어떤 취향이 존재하는지 보여주는 지도"**

입니다.

사용자의 정확한 위치를 보호하면서
지역 단위의 익명 취향 데이터를 통해
사람과 상품, 콘텐츠를 연결합니다.
