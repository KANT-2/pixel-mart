# PIXEL MART — PIXEL LOCAL 운영정책

## 1. 문서 목적

본 문서는 PIXEL MART의 지역 기반 취향 커뮤니티 기능인
**PIXEL LOCAL**의 서비스 운영 기준을 정의합니다.

PIXEL LOCAL은 단순한 위치 기반 중고거래 서비스가 아닙니다.

사용자의 지역과 취향을 연결하여

취향 발견
→ 같은 취향 사용자 존재 확인
→ 콘텐츠 탐색
→ 상품 발견
→ 거래 / 교환
→ 커뮤니티 참여
→ 재방문

으로 이어지는 경험을 만드는 것을 목표로 합니다.

---

# 2. 서비스 정의

PIXEL LOCAL은

**지역 + 취향 + 상품 + 사람 + 콘텐츠**

를 연결하는 지역 기반 취향 커뮤니티입니다.

일반적인 지역 서비스가

지역
→ 사람
→ 거래

를 중심으로 한다면,

PIXEL MART는

지역
→ 취향
→ 사람
→ Deskterior
→ 상품
→ 거래 / 교환
→ 커뮤니티

까지 연결합니다.

---

# 3. 핵심 목표

PIXEL LOCAL의 목표는 단순히 지역 기능을 추가하는 것이 아닙니다.

## 고객 관점

사용자가 다음 경험을 할 수 있도록 합니다.

> "내 주변에도 나와 같은 것을 좋아하는 사람이 있다."

이를 통해 취향에 대한 소속감과 참여 동기를 제공합니다.

## 서비스 관점

상품 구매 목적이 없어도 사용자가 다시 방문할 이유를 만듭니다.

## 비즈니스 관점

지역별 취향과 상품 수요를 익명으로 축적하여
향후 상품 추천, 공동구매, 재고, 팝업스토어, 상품 소싱 등에 활용할 수 있는 기반을 마련합니다.

---

# 4. PIXEL LOCAL 핵심 기능

PIXEL LOCAL은 다음 기능으로 구성합니다.

1. 덕력지도
2. 지역별 취향 사용자 집계
3. PIXEL LOCAL × Deskterior
4. Local Trade
5. HAVE / WANT Exchange
6. Local Wish Map
7. 지역 기반 공동구매 확장
8. 지역 기반 Tournament 확장

각 기능은 독립적인 기능이 아니라 하나의 사용자 흐름으로 연결합니다.

---

# 5. 기본 지역 정책

## 5.1 지역 노출 단위

사용자의 정확한 주소나 위치는 공개하지 않습니다.

서비스에서는 다음 수준까지만 활용합니다.

- 시
- 구
- 동 수준의 넓은 생활권
- 서비스에서 정의한 지역 Zone

예:

분당구  
판교  
정자동

정확한 주소, 건물, 아파트 동·호수 등은 공개하지 않습니다.

---

## 5.2 정확한 위치 비공개

다른 사용자가 확인할 수 있는 정보는 다음과 같습니다.

가능:

- "분당구 사용자"
- "판교 지역"
- "약 2km 이내 교환 가능"

불가:

- 정확한 GPS 좌표
- 실제 주소
- 거주 건물
- 특정 개인의 실시간 위치

### 운영 원칙

지역은 사람을 연결하기 위한 정보이지,
개인을 특정하기 위한 정보가 아닙니다.

---

# 6. 취향 프로필 정책

사용자는 자신의 취향을 직접 선택할 수 있습니다.

예:

캐릭터

- 오로치마루
- 나루토
- 슬라임

스타일

- Retro
- Cute
- Neon
- Dark
- RPG

관심 상품

- Keycap
- Figure
- Desk Mat
- Mood Lamp

게임 / 작품

- Naruto
- Retro RPG
- Pixel Game

사용자가 선택한 취향은 PIXEL LOCAL 추천과
덕력지도 집계에 활용할 수 있습니다.

---

# 7. 취향 정보 공개 정책

취향 정보는 사용자가 공개 범위를 선택할 수 있도록 하는 방향을 원칙으로 합니다.

예:

공개

- 내가 선택한 캐릭터
- Deskterior
- 교환 희망 상품

비공개

- 구매금액
- 장바구니 전체
- 정확한 위치
- 개인 검색 기록

### 핵심 원칙

개인의 구매 행동을 그대로 노출하지 않고,
필요한 경우 익명 집계된 형태로만 서비스에 활용합니다.

---

# 8. 덕력지도 연결

덕력지도에서는 특정 사용자를 직접 표시하지 않고
지역 단위의 취향 인원만 보여줍니다.

예:

분당구

- 오로치마루 팬 18명
- 나루토 팬 42명
- Retro Gamer 67명
- 키캡 수집러 31명
- PIXEL DESK 사용자 26명

사용자가 항목을 선택하면 다음 화면으로 연결할 수 있습니다.

오로치마루
→ 관련 상품
→ 지역 Deskterior
→ 교환 가능 상품
→ 관련 게시물

---

# 9. PIXEL LOCAL × Deskterior 정책

지역과 Deskterior 콘텐츠를 연결합니다.

예:

판교 인기 PIXEL DESK

사용 상품:

- Purple Keycap
- Dungeon Desk Mat
- Pixel Lamp

상품 상세 화면에서는 다음 정보를 제공할 수 있습니다.

> 이 상품을 사용한 판교 Desk 12개

사용자가 해당 문구를 클릭하면
실제 사용자들의 Deskterior 콘텐츠를 확인할 수 있습니다.

---

# 10. Local Trade 정책

PIXEL LOCAL에서는 사용자가 보유한 굿즈를
지역 기반으로 판매할 수 있는 기능으로 확장할 수 있습니다.

거래 게시물에는 다음 정보만 노출합니다.

- 상품명
- 상품 상태
- 희망 가격
- 희망 지역
- 상품 사진
- 거래 가능 방식

정확한 거래 장소는 거래 당사자 간 협의 이후 결정합니다.

---

# 11. HAVE / WANT Exchange 정책

랜덤 굿즈 또는 중복 굿즈를 교환할 수 있도록
HAVE / WANT 구조를 제공합니다.

예:

HAVE

카카시 키링

WANT

오로치마루 키링

서비스는 서로의 조건이 맞는 사용자를 탐색합니다.

예:

A 사용자

HAVE: 카카시  
WANT: 오로치마루

B 사용자

HAVE: 오로치마루  
WANT: 카카시

결과:

MATCH

---

# 12. Exchange Matching 우선순위

교환 추천은 다음 기준을 활용할 수 있습니다.

1. HAVE / WANT 일치
2. 지역 거리
3. 상품 상태
4. 거래 가능 시간
5. 사용자 신뢰도

이번 프로젝트에서는 Mock Data 기반으로
HAVE / WANT 일치와 지역 정보까지만 구현합니다.

---

# 13. 거래 안전 정책

실제 서비스 확장 시 거래 안전을 위해 다음 정책을 적용합니다.

- 정확한 주거지 공개 금지
- 공개 게시글에 연락처 작성 금지
- 외부 결제 유도 제한
- 신고 기능 제공
- 거래 완료 후 상태 변경
- 반복 신고 사용자 제한
- 비정상 거래 패턴 모니터링

PIXEL MART는 거래 당사자의 개인정보 노출을 최소화하는 것을 기본 원칙으로 합니다.

---

# 14. 사용자 신뢰 정책

향후 실제 서비스에서는 다음과 같은 활동을 기반으로
사용자 신뢰 정보를 제공할 수 있습니다.

예:

- 거래 완료 횟수
- 교환 완료 횟수
- 신고 여부
- Deskterior 활동
- 커뮤니티 활동

단순 활동량만으로 신뢰도를 판단하지 않고,
거래 완료 및 운영정책 준수 여부를 중심으로 설계합니다.

---

# 15. Local Wish Map

개인의 장바구니 또는 찜 목록을 그대로 공개하지 않습니다.

지역별 관심 상품을 익명 집계하여 보여줍니다.

예:

판교에서 많이 원하는 상품

1. Hello Kitty Keycap — 38명
2. Orochimaru Figure — 27명
3. Pixel Slime Lamp — 21명

### 활용

지역의 관심 수요가 일정 기준 이상 쌓일 경우

- 공동구매
- 재입고
- 지역 팝업
- 상품 소싱
- 지역 프로모션

등으로 확장할 수 있습니다.

---

# 16. 개인 장바구니 비공개 원칙

다음 데이터는 개인 단위로 다른 사용자에게 공개하지 않습니다.

- 장바구니 내용
- 구매 내역
- 검색 내역
- 최근 본 상품
- 정확한 결제금액

서비스에서는 필요한 경우 익명화·집계된 통계만 제공합니다.

---

# 17. 공동구매 확장 정책

특정 지역에서 동일 상품에 대한 관심 사용자가 일정 기준 이상 발생하면
공동구매 후보로 전환할 수 있습니다.

예:

판교

Pixel Slime Lamp

관심 사용자 50명

→ 공동구매 후보

향후 운영자는 다음 데이터를 활용할 수 있습니다.

- 지역
- 관심 사용자 수
- 상품
- 예상 수요
- 기간

---

# 18. 지역 Tournament 확장

Deskterior Tournament와 PIXEL LOCAL을 연결합니다.

예:

- 분당 PIXEL DESK CUP
- 판교 BEST PIXEL DESK
- 강남 RETRO DESK WEEK

지역 커뮤니티가 성장한 이후
지역별 Tournament를 운영할 수 있습니다.

---

# 19. Cold Start 정책

PIXEL LOCAL은 초기 사용자가 적을 경우
지역별 콘텐츠가 비어 보일 수 있습니다.

이를 Cold Start 문제라고 정의합니다.

초기 단계에서는 다음 방식으로 해결합니다.

### 1단계

PIXEL MART 상품 콘텐츠 제공

### 2단계

Sample Deskterior 콘텐츠 제공

### 3단계

Mock 지역 취향 데이터 제공

### 4단계

실제 사용자 활동이 발생하면
Mock 데이터를 실제 데이터로 점진적으로 대체

실제 서비스에서는 Mock 데이터를 실제 사용자 데이터처럼 오인시키지 않도록
샘플 또는 추천 콘텐츠임을 명확하게 표시해야 합니다.

---

# 20. Empty State 정책

해당 지역에 콘텐츠가 없을 경우

"사용자가 없습니다."

로 끝내지 않습니다.

예:

현재 판교 지역의 오로치마루 교환 상품이 없습니다.

대신:

- 분당구 전체에서 보기
- 관련 상품 보기
- 교환 요청 등록
- 관심 지역 등록

등의 다음 행동을 제공합니다.

---

# 21. 부정 이용 정책

다음 행위를 제한합니다.

- 동일 상품 반복 등록
- 허위 거래 등록
- 동일 콘텐츠 반복 게시
- 신고를 이용한 사용자 괴롭힘
- 지역 정보 조작
- 자동화된 비정상 활동
- 상품과 관련 없는 광고 게시

운영정책 위반 시

경고
→ 기능 제한
→ 일정 기간 이용 제한
→ 계정 제한

순으로 대응할 수 있습니다.

---

# 22. 신고 정책

신고 사유 예:

- 허위 거래
- 부적절한 콘텐츠
- 스팸
- 욕설 / 괴롭힘
- 개인정보 노출
- 사기 의심
- 운영정책 위반

신고 접수 사실만으로 자동 제재하지 않고
운영 검토 후 처리하는 것을 원칙으로 합니다.

---

# 23. 지역 추천 정책

사용자가 자신의 지역을 선택하지 않은 경우
무조건 위치 권한을 요구하지 않습니다.

사용자가 직접 지역을 선택할 수 있도록 합니다.

예:

내 지역 설정

분당구
→ 판교
→ 정자동

위치 권한은 서비스 이용에 필요한 최소 범위로 제한합니다.

- 사용자가 "내 위치로 찾기"(동네 등록) 또는 "내 위치로 보기"(덕력지도)를 눌렀을 때만 위치 권한을 요청합니다.
- 좌표는 브라우저 안에서 가까운 지역을 찾는 데만 쓰고, 서버로 보내거나 저장하지 않습니다.
- 동네 등록은 찾은 지역을 사용자가 확인·저장해야 반영되며, 서버에는 지역 코드만 저장합니다.
- 위치 권한을 거부해도 직접 지역 선택으로 모든 기능을 이용할 수 있습니다.

자세한 기준은 `DUKRYEOK_MAP_POLICY.md` 4.1을 따릅니다.

---

# 24. 추천 알고리즘 기본 원칙

PIXEL LOCAL 추천은 다음 요소를 조합할 수 있습니다.

- 사용자의 지역
- 선택한 취향
- 관심 캐릭터
- 관심 상품
- Deskterior 활동
- 검색 / 클릭 행동

그러나 단일 취향만 반복 노출하지 않고
새로운 상품과 취향을 발견할 수 있는 탐색 영역을 함께 제공합니다.

---

# 25. 데이터 활용 원칙

PIXEL LOCAL에서 발생한 행동 데이터는
다음 목적으로 활용할 수 있습니다.

- 상품 추천
- 인기 상품 분석
- 지역별 상품 수요 분석
- 공동구매 후보 선정
- 지역 팝업 후보 선정
- 상품 기획
- 재고 전략

개인 사용자의 행동을 공개하는 것이 아니라
집계 데이터를 활용하는 것을 원칙으로 합니다.

---

# 26. 핵심 KPI

PIXEL LOCAL의 성공 여부는 단순 회원 수만으로 판단하지 않습니다.

### Acquisition

- PIXEL LOCAL 진입 사용자 수
- 지역 설정 완료율

### Engagement

- 덕력지도 클릭률
- Deskterior 조회 수
- 교환 매칭 조회 수
- 지역 콘텐츠 조회 수

### Community

- 콘텐츠 생성 사용자 비율
- 교환 등록 수
- 거래 등록 수
- 투표 참여율

### Commerce

- Local → 상품 상세 이동률
- Deskterior → 상품 상세 이동률
- 관심 상품 → 장바구니 전환율

### Retention

- 7일 재방문율
- Tournament 재참여율
- Local 콘텐츠 재방문율

# 27-1. 동네 선물 정책

거래소에서 이웃의 글(HAVE·WANT·SELL)을 보고 **PIXEL MART 상품을 선물**할 수 있습니다.

- **시작 위치**: 교환 창·거래 카드의 "🎁 선물하기" — 받는 사람은 그 글을 올린 이웃 (익명이라 다른 곳에서 받는 사람을 고를 수 없음)
- **결제**: 데모 결제(실제 결제 없음). 결제 시점 가격으로 선물이 만들어지고 받기 대기 상태가 됩니다.
- **받기·거절**: 받는 사람이 마이페이지 선물함에서 **자기 이름·주소를 직접 입력**해 받으면, 받는 사람의 주문이 생기고 배송 흐름을 따릅니다. 거절하면 보낸 사람에게는 "거절 · 환불(데모)"로 보입니다.
- **익명**: 보낸 사람·받는 사람은 서로를 **"이웃 플레이어"**로만 봅니다. 닉네임·계정·지역 코드·**주소는 상대에게 보이지 않습니다.**
- **제한**: 내 글, 숨김·완료된 글, 샘플 글에는 선물할 수 없습니다. 메시지(100자)에 연락처·정확한 장소는 적을 수 없습니다(11장 기준과 같음). 수량은 1~9개.

# 28. 서비스 성장 구조

PIXEL LOCAL은 다음 선순환을 만드는 것을 목표로 합니다.

사람
→ 취향 데이터
→ 콘텐츠
→ 커뮤니티
→ 상품 발견
→ 거래 / 구매
→ 활동 데이터
→ 더 좋은 추천
→ 더 많은 사람

사용자가 많아질수록
서비스 안의 콘텐츠와 거래 가능성이 증가하고,
그 결과 서비스의 가치가 증가하는 구조를 지향합니다.

# 29. 장기 확장 방향

PIXEL LOCAL은 장기적으로

지역
+ 취향
+ Deskterior
+ 거래
+ 공동구매
+ 오프라인 이벤트

를 연결하는 플랫폼으로 확장할 수 있습니다.

예:

온라인 취향 발견
→ 지역 Desk Tournament
→ 지역 공동구매
→ PIXEL MART POP-UP
→ 오프라인 커뮤니티

# 30. 핵심 운영 원칙

PIXEL LOCAL은

**"사람의 위치를 보여주는 서비스"**

가 아니라

**"같은 지역 안에 존재하는 취향을 발견하도록 돕는 서비스"**

로 운영합니다.

개인의 위치와 행동은 보호하면서,
집계된 지역과 취향 데이터를 통해
사용자 간 연결과 새로운 상품 발견을 지원합니다.
