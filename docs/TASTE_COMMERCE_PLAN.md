## 1. 한 줄 컨셉

**"취향으로 만든 내 캐릭터가 아이템을 장착하고, 같은 취향의 이웃을 만나는 동네 게임형 쇼핑몰"**

| 게임 개념 | PIXEL MART | 축 |
| --- | --- | --- |
| 내 캐릭터 | 픽셀 아바타(AI 생성 가능) + 취향 | 정체성 |
| 장비 | 구매한 상품 (키캡 피팅룸에서 내 키보드에 끼워 보기) | 이커머스 |
| 월드맵 | 덕력지도 (동네별 취향 분포) | 커뮤니티 |
| 파티원 | 같은 동네·같은 취향 이웃 (이웃 카드·거래·교환·선물) | 커뮤니티 |

### 핵심 연결 흐름

```
① 취향 표현 → ② 굿즈 발견 → ③ 쇼핑 → ④ 커뮤니티 참여 → (하트·코인·뱃지) → ① 재방문
```

| 단계 | 현재 | 근거 |
| --- | --- | --- |
| ① 취향 표현 | 🔶 아바타 ✅, 취향은 작품 4개뿐 | `backend/seed/interests.json` |
| ② 굿즈 발견 | 🔶 취향 → 상품이 **이름 글자 검색** (`/products?q=취향`) | `utils/local.ts` `interestProductHref` |
| ③ 쇼핑 | ✅ 상품·장바구니·가상 주문·배송·리뷰·Q&A·키캡 피팅룸 | |
| ④ 커뮤니티 | ✅ 덕력지도·이웃 카드·거래/교환·위시맵·선물 | |

→ 이번 기획의 목표: **①·②를 세분화된 취향 기준으로 다시 연결**

## 2. 취향 세분화 (교수님 피드백, 결정 D1)

### 2-1. 현업 사례

| 서비스 | 방식 | 가져온 점 |
| --- | --- | --- |
| 당근 | 운영자 고정 카테고리 + 사용자 **키워드 알림** + 관심사 모임 분리 | 취향을 숙제처럼 묻지 않고 "알림 받고 싶은 것"으로 수집 |
| 넷플릭스 | 콘텐츠에 무드·소재 등 세부 태그를 붙여 세부 장르 생성 | **상품 쪽에 태그**를 촘촘히 |
| 핀터레스트 | 가입 때 관심사 몇 개 선택 → 행동으로 계층형 분류 정교화 | 첫 선택은 가볍게, 정교화는 행동으로 |
| 무신사 | 상품 카테고리와 별개로 **스타일 태그** | "무엇"과 "어떤 느낌"을 다른 축으로 |
| 번개장터 | 덕질 카테고리 + 글의 #태그 | 끝없이 늘어나는 작품명은 자유 태그로 |
| 왓챠 | 평가 기록 → "취향 분석" 카드 | 행동 결과를 "나는 이런 사람"으로 돌려줌 |

### 2-2. 현재 구현

- 취향 = 작품 4개: 나루토 · 레트로 RPG · 픽셀 게임 · 던전 크롤러 (`type: work`)
- 이전의 캐릭터·스타일·상품종류 태그는 PR #130에서 삭제됨
- `interests` 테이블에는 `type`, `parent_id`(계층)가 남아 있어 **확장은 시드 수정만으로 가능**
- 문제: "레트로 RPG", "던전 크롤러"는 작품이 아니라 장르 / 상품과 연결 고리 없음

### 2-3. 제안: 취향 5축

| 축 | 질문 | 관리 주체 | 예시 |
| --- | --- | --- | --- |
| ① 세계관 | 어떤 세계를 좋아하나 | 운영자 (고정 5개) | 판타지 RPG · 던전 탐험 · 우주 아케이드 · 게임 시스템 · 힐링 생활 |
| ② 작품 › 캐릭터 | 그 안에서 무엇을 | 사용자 자유 태그 → 운영자 승격 | 레트로 RPG › 슬라임 |
| ③ 클래스 | 나는 어떤 캐릭터 타입 | 사용자 선택 (고정 6개) | 용사 · 마법사 · 탐험가 · 몬스터파 · 보스파 · 펫파 |
| ④ 무드 | 어떤 분위기 | 운영자 (고정 5개) | 레트로 · 귀여움 · 네온 · 다크 · 클래식 판타지 |
| ⑤ 덕질 방식 | 어떻게 즐기나 | 시스템 자동 계산 | 수집형 · 꾸미기형 · 교환형 · 선물형 |

운영 규칙
- 자유 태그(작품·캐릭터)는 **20명 이상**이 쓰면 공식 필터로 승격. 그 전에는 지도에 노출하지 않음 (소수 취향으로 개인 특정 방지)
- 동의어는 주 1회 운영자가 합침 (나루토 = NARUTO). 공식 이미지·로고 없이 텍스트 태그만
- 덕질 방식은 찜·구매·교환·선물 건수 비율이 가장 큰 쪽 (활동 5건 이상일 때만)

| 선물 보내기 완료 (받는 사람이 수락했을 때, 보낸 사람만) | +10 | 같은 선물 한 번, 하루 3건 |
| (정의만 있고 사용처 없음) 유효한 커뮤니티 기여 | +5 | 하루 5건 |

공개 범위 ✅
- 정확한 점수·코인 수·다음 하트까지: **본인만** (`GET /api/users/me/activity`)
- 이웃 카드(하트·레벨·코인 구간·대표 뱃지): **"지도에서 내 이웃 카드 보여 주기"(기본 OFF) 동의자만**
- 닉네임·취향·WANT 수는 각각의 공개 동의가 있을 때만

### 5-2. 기준 원칙 (발표용)

- **하트 = 동네 참여도, 코인 = 교환 실적, 뱃지 = 처음 해낸 일과 대회 기록**
- 세 가지 모두 **구매 금액과 무관** (돈으로 살 수 없음) — 단, 결정 D2(구매 순위)가 이 원칙과 충돌
- 같은 일은 한 번만, 반복 활동은 하루 상한

### 5-3. 문제점과 보완 제안

| 문제 | 영향 | 보완 |
| --- | --- | --- |
| 거래 완료를 혼자 누를 수 있음 (D3) | 빈 글 → 완료로 하루 +60점, 코인도 증가 | 🔷 거래 상대 선택 + 상대 승인 시 **양쪽** 적립 |
| 선물은 보낸 사람만 점수 | 받는 사람의 참여(수락)는 반영 안 됨 | 🔷 의도된 것인지 팀 확인 (보낸 사람만 = "주는 문화" 강조라면 유지) |
| 같은 두 사람 반복 | 친구끼리 선물을 반복해 점수 쌓기 | 🔷 같은 상대와는 30일에 1회만 적립 |
| `contribution` 규칙 미사용 | 기준 불명확 | 🔷 쓰임새 정하거나 삭제 |
| 점수 회수 없음 | 사기 거래 점수 유지 | ⏳ 신고 확정 시 회수 |

### 5-4. 뱃지 (BE-C, 이슈 #30 — 제안)
